# 設計・実装方針

この資料は、実装時に参照する設計上の不変条件をまとめたものです。常時読み込むエージェント指示は簡潔に保ち、詳細な方針はここで管理します。

- **API 契約**: API の入出力は Zod で検証し、公開 API は `@hono/zod-openapi` の OpenAPI 契約へ登録する。仕様は `/api/doc` で確認できる状態を保つ。
- **フロントエンドのデータ取得**: サーバー状態は TanStack Query で扱う。API 呼び出しは `apps/web/src/api.ts` にまとめ、コンポーネント内に直接 `fetch` を増やさない。
- **UI スタイリング**: StyleX を標準スタイリング手段とする。コンパイルが必要なため、`stylex.create` を通常のランタイム CSS-in-JS として扱わない。
- **共有スキーマの変更**: スキーマを変更したら、API 実装・OpenAPI 契約・ユニットテストを同時に更新する。
- **データベースの変更**: DB スキーマを変更したら Prisma migration を追加し、既存 migration を書き換えない。
