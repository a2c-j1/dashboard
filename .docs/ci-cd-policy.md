# CI/CD方針

## 目的

AIに実装を自走させ、開発速度を保つ。同時に、範囲外変更・破壊的変更・セキュリティ事故を機械的な境界で止める。人は、機械で判定しにくい目的や設計上の判断に集中する。

## 基本原則

- 長い指示やチェックリストをAIに常時読ませず、実行可能なCI・リポジトリ設定を優先する。
- 自動チェックは「検出したら失敗」にできる、再現可能で説明可能なものから導入する。
- 自動化できない判断は無理に形式化せず、停止条件と人レビュー条件として短く定義する。
- 既存の開発フローを壊さず、失敗時に修正箇所が分かるフィードバックを返す。

## 責務の分離

- `AGENTS.md`：AIが作業開始時に知るべき不変ルール、変更境界、停止条件、必要な検証だけを置く。実装手順や基準一覧は増やさない。
- GitHub Actions：format、lint、unit test、build、E2E、Semgrepなど、繰り返し判定できる品質ゲートを実行する。
- PRテンプレート：その変更の目的、受入条件、影響範囲、例外理由など、作業単位で必要な情報を求める。
- `.docs/`：人間が判断する背景、運用方針、例外、導入計画を記録する。`review-criteria.md` は自動化候補の台帳であり、常時必読のガイドにはしない。

## AIの自律範囲と停止条件

AIは、IssueやPRで示された目的・受入条件・対象パスの範囲内で、実装、テスト追加、既存テストの更新、必要な局所リファクタリングを自律して行う。完了時には変更理由と検証結果を報告する。

次の場合は変更を広げず、理由と選択肢を提示して人の判断を求める。

- 指定された対象パスや目的を越える変更が必要になった。
- 公開API、共有スキーマ、DBスキーマ、認証・認可、CI設定を変更する。
- 既存データを不可逆に変える、migrationの扱いが不明、またはロールバック方法がない。
- 新しい外部依存、秘密情報、権限、外部サービスへの書き込みが必要になる。
- CIの失敗を無視する、テストを削除・弱める、Semgrep警告を抑制する必要がある。

## 現行CIと段階的な自動化

現在の `quality.yml` は、PRと`main`へのpushで Node.js 24・`npm ci`を使用し、format check、lint、test、build、Playwright E2E、Semgrepを実行する。したがって、まずこの既存ゲートを必須チェックとして維持する。

Semgrepは実行経路があるが、`.semgrep.yml` のカスタムルールは本番コードの`console.log`検出（開発環境内は除外）の1件だけである。これを認可やインジェクションの網羅的な保証とは扱わない。

自動化は次の順で、各段階の効果と誤検知を確認してから進める。

1. **現行ゲートの固定**：既存のformat/lint/test/build/E2E/SemgrepをPRの必須ステータスにする。
2. **変更整合性の検出**：API・共有スキーマ・Prisma migrationなど、関連ファイルの更新漏れを差分から検出する。まず誤検知の少ない規則に限定する。
3. **境界の静的検査**：コンポーネント内の直接`fetch`、危険な秘密情報・ログ・入力シンクなど、明確なパターンだけをESLint/Semgrepで追加する。
4. **契約と重要フロー**：OpenAPIの実装整合性、重要UIフロー、アクセシビリティを既存テストの範囲で段階的に検査する。

各段階で新しい外部依存を増やす場合は、目的・利用箇所・代替しない理由を先に記録し、承認を得る。自動化候補の優先順位は`review-criteria.md`で管理し、導入済みの項目だけをCIの事実として扱う。

## 運用ルール

- 文書に新しい規則を足す前に、CIや既存設定で機械的に検証できないか確認する。
- 同じルールを`AGENTS.md`、PRテンプレート、`.docs/`に重複記載しない。正本を一か所に置き、他は参照に留める。
- AIが毎回読む必要のない詳細、導入候補、検討履歴は常時コンテキストから外す。
- 自動チェックを追加したら、対象・失敗条件・例外方法を短く記録し、台帳の候補を更新する。
- 誤検知、重複、現行運用に不要になった記述は削除する。文書の増加ではなく、判断負荷の削減を成果とする。

## 完了条件

- AIが対象範囲内で自律実装でき、範囲外・高リスク変更では停止する。
- PRで現行の品質ゲートが再現可能に実行され、失敗がマージを止める。
- API・スキーマ・DB・セキュリティに関する明確な更新漏れを自動検出できる。
- 人が確認する項目は、目的・設計・例外など自動判定できない判断に絞られている。
- `AGENTS.md`や常時参照するdocsが、CIで代替できる規則の追加によって肥大化していない。
